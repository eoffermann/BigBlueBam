# BigBlueBam Documentation

This directory holds the project's written documentation. It is intentionally
lean: evergreen specs, how-to guides, the per-app docs that feed the in-app Help
system, and the small set of notes and plans that back work currently in flight.
Completed plans and dated audits are not kept here; they live in git history if
you ever need them.

For the project overview, tech stack, and architecture orientation, start with
the root [`../README.md`](../README.md) and [`../CLAUDE.md`](../CLAUDE.md).

## Layout

| Path | What lives here |
|---|---|
| [`reference/`](./reference/) | Evergreen specs that describe the system as it is. |
| [`guides/`](./guides/) | How-to docs: set up, develop, deploy, operate. |
| [`apps/`](./apps/) | Per-app docs (one folder per app), generated by the docs pipeline and served by the in-app Help Center. |
| [`plans/`](./plans/) | Plans for work still in flight. Shipped plans are removed (the code is the record). |
| `deploy/`, `history/`, `auto/`, `images/` | Deploy-variable decisions, one kept recovery record, generated build artifacts, shared diagrams. |

## Per-app docs

[`apps/<name>/`](./apps/) for each of the 16 apps (bam, banter, beacon, bearing,
bench, bill, blank, blast, blueprint, board, bolt, bond, book, brief, bureau,
helpdesk). Each folder carries `help.md` (the source the in-app Help Center
renders), plus `guide.md`, `marketing.md`, `mcp-tools.md`, `_narrative.md`,
`_marketing_hook.md`, and `screenshots/`. These are generated from code; never
hand-edit the derived `help-index.json`.
